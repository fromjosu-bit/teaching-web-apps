# 계정·학습 기록 보안 검토

2026-10-17 (Asia/Seoul).

## 접근 제어

- Supabase Auth의 비밀번호 인증을 사용합니다. 브라우저에는 publishable 키만 포함합니다.
- 실제 이메일 없이 내부 계정 주소를 사용하며 사용자 승인에 따라 새 전용 프로젝트의 이메일 확인을 해제했습니다. 서버 최소 비밀번호 길이는 8자입니다.
- learning_records에 RLS 활성화, authenticated의 본인 행 SELECT/INSERT만 허용합니다. anon 권한과 클라이언트 UPDATE/DELETE는 없습니다.
- INSERT 컬럼을 id·game_id·correct_count로 제한합니다. user_id는 auth.uid(), 시각은 서버 기본값, 점수는 정답 수로 생성됩니다. 소유자·점수·시각을 직접 지정할 수 없습니다.
- 통계 함수는 SECURITY INVOKER이며 본인 UID와 RLS를 적용합니다. user_metadata를 권한 판단에 사용하지 않습니다.
- owner·played_at·id 인덱스 사용. 최근 100판 조회와 전체 집계입니다.
- 세션과 미저장 기록은 탭의 sessionStorage에 보관하며 비밀번호는 저장하지 않습니다. 로그아웃 시 이전 계정 기록을 비웁니다.
- 저장 실패 시 같은 UUID로 재시도하여 중복 저장을 방지합니다. 미저장 기록이 있으면 다음 게임 시작 전 저장하도록 안내합니다.
- Vercel 정식 운영 주소는 공개하고 개별 배포·미리보기 URL은 Standard Protection으로 보호합니다. 학습 기록은 Supabase 인증과 RLS로 제한합니다.
- 배포 대상은 dist의 정적 파일 4개입니다. .env·관리자 키·CLI 상태·합성 계정 자격 증명을 제외합니다.

## 실행 검증

- 문항 검사: 4개 게임, 24개 문항 통과.
- 아이디·비밀번호 길이, 기록 필드 제한·정답 수 검증 테스트 통과.
- 실제 Supabase 합성 계정 2개로 가입·본인 저장/조회/통계 통과. 다른 계정 조회는 빈 결과, 비로그인 조회·소유자/점수 위조·잘못된 정답 수·클라이언트 수정/삭제는 거부됨을 확인했습니다.
- 실제 배포 브라우저에서 로그인 → 5문제 완료 → 60점 저장 → 새로고침 → 기록 재조회 → 로그아웃/통계 초기화를 확인했습니다.
- npm audit 0 vulnerabilities, 정적 빌드 성공.
- Supabase 보안 진단: DB 경고는 없고 Auth의 유출 비밀번호 검사 비활성 경고 1건이 남습니다. 해당 기능은 현재 무료 요금제에서 사용할 수 없어 유료 업그레이드는 하지 않았습니다.

## 제한

연습용 기록입니다. 정답 수를 클라이언트가 제출하므로 시험용 부정행위 방지 성적 체계가 아닙니다. 프로젝트 관리자는 기록에 접근할 수 있습니다. 실제 이메일을 받지 않아 이메일 복구는 사용할 수 없고 담당 교사의 본인 확인이 필요합니다. 무료 할당량·인증 시도 제한을 초과하면 사용이 일시 제한될 수 있습니다.
